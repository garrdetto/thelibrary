# Leaderboards and knocked-out notices

Module score boards, run checkpoints and top-3 notices. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- `src/server/routes/scores.ts`: `/api/module-scores` leaderboards for embedded modules (GET `?module=`, POST `score` / `reset-records`). Board settings live in `src/lib/module-scores.ts`.
- `src/server/score-notices.ts` + `src/server/routes/score-notices.ts`: "knocked out" notices. Module scores, racing laps (all tracks, incl. Short Track Showdown) and Fairway Nine records save through `saveWithKnockouts`, which reads the board's top 3 before and after the write and, for every other player whose top-3 entry moved down, upserts one row per player and module in D1 `score_notices` (migration 0029, also created on first use; a newer notice for the same module replaces the older one, so they never stack). `/api/score-notices` GET (signed in) lists them; POST `{action:'clear', game?}` clears one or all. `src/components/ScoreNotices.tsx` shows them as yellow ribbons at the top of the home page ("[User] has knocked you out of 1st place on [module]!").
- Leaderboards: a module can have several boards (one per mode): list them in `scoreBoardGroups` and give each entry a `parent` and `label` in `scoredModules`; the page then shows them as tabs. 2048, Chopper Cave, BotWreck 3D and the newer single-file modules load `public/modules/module-scores.js` and call `tlScores.submit(module, value)`; it posts to `/api/module-scores` and messages the parent `{type:'tl-score-saved'}` so `ModuleScoreboard.tsx` (shown under the module frame) refreshes. Points boards (2048, Chopper Cave, BotWreck 3D, Tetra Drop, Bubble Shooter, Blockhead Siege, Demo Derby) also call `tlScores.progress` / `Scores.progress` while a run is going: the run is checkpointed every 15 s, flushed on `pagehide`, hidden tab and `online`, and kept in the localStorage outbox `tl-score-outbox` until the server confirms it (resent on the next visit), so a run cut short by closing the page, a disconnect or a power-off still counts. The outbox is only a delivery queue; D1 stays the record. Every POST carries a run id and the server upserts `<user>:<run>`, keeping the better value, so checkpoints and the final save make one row per run. Time boards (`order: 'asc'`) and Fairway Nine rounds and matches save only finished runs, because an unfinished time or round can't be ranked. Boards list every saved result, top 10, so one player can hold several places. Short Track Showdown uses the racing lap records (`LapRecordBoard`) instead. Short Track Showdown runs on Babylon.js (WebGPU with WebGL2 fallback) with Havok (`modules-src/shorttrack/next/`, phases in `docs/shorttrack/PLAN.md`). The next engine is the default since the cut-over; `?engine=classic` keeps the classic three.js renderer and vehicle model for one release, and a follow-up removes it. The module draws through Babylon (`next/render/presenter.ts` plus `bridge.ts`, which mirrors the three.js scene graph each frame), so scene changes made in `render-three/main.js` show on both engines (and if Babylon cannot start at all, the classic renderer draws the page); keep three `ShaderMaterial`/`onBeforeCompile` out of new scene code, since the bridge cannot carry custom shaders (the crowd's cheer is re-created as a Babylon plugin, found through `material.userData.crowd`). Next-engine quality is `?quality=low|medium|high|ultra` (default: the module's own setting), tone mapping is PBR Neutral unless `?tonemap=aces`, and `?fx=-taa,+ssao` switches single effects (`next/render/quality.ts`). The next engine also drives the cars with the next vehicle model (`next/sim/dynamics.ts`: four tires, load transfer, banking, aero, drafting; `&physics=classic` keeps the old model); it is calibrated so AI laps stay within 3 % of the classic fixtures on asphalt and 5 % on dirt (`tests/physics.test.ts`, which also runs a 20-car 25-lap soak), its laps post to versioned record keys (`prison-v2`, `shorttrack-v2`, `dells-v2`, `dellswide-v2`, `dirt-v2`) while the classic keys are read-only (the server refuses new laps on them; nothing is deleted, and the board shows them under a Classic tab), `hello` carries the model as `ph` so rooms never mix models, and Havok only throws cosmetic debris (`next/render/debris.ts`): chassis and wall contact stay in the deterministic sim. The classic model is pinned to the classic behaviour by golden tests against recordings made with the classic page's `?record=1` hook (`scripts/shorttrack-reference.mjs`, fixtures in `modules-src/shorttrack/tests/fixtures/`, screenshots in `docs/screenshots/shorttrack/`); change sim behaviour only with re-recorded fixtures.
