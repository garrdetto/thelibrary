# Site shell, chat, themes and shared UI

Styling, the fox dollar sign, mobile full screen, the module catalog, group chat, themes and record resets. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- `src/styles.css`: all styling, CSS tokens, site themes, responsive layouts, reduced-motion and focus states. The "Mobile shell" block at its end: the off-canvas drawer and 56 px topbar apply at `max-width: 650px`, on touch screens up to 900 px wide or 500 px tall, and in windows under 440 px tall (the theme picker moves into the drawer on phones held upright; sign-out is an icon); on short landscape touch screens the topbar is 52 px and hides in a module view (`.main-panel.is-playing`), where the frame bar's menu button (`.play-frame-menu`) opens the drawer. There the play frame is `100dvh - --tl-ribbon-h - --tl-top-h` tall so it fits the screen with the score boards below. Edges use `env(safe-area-inset-*)` (`viewport-fit=cover` in `__root.tsx`), and the ribbon adds the bottom inset to `--tl-ribbon-h`. On `(hover: none)` screens the cards' Launch label always shows.
- Currency symbol: every `$` on the site and in the learning modules is drawn as the owner's fox dollar sign. `public/fox-dollar.js` (loaded first in `src/routes/__root.tsx`, in every built module page by the `foxDollar` plugin in `vite.modules.ts`, and by hand in the single-file pages in `public/modules/`) registers the font `TL Fox Dollar` (one glyph at U+0024, inlined) and prefixes it onto every canvas 2D `font` string, so canvas, three.js and Babylon GUI text get it too. DOM text gets it from the font stacks: every `font-family`, `font` shorthand, `--*font*` variable and Tailwind `--font-sans` starts with `'TL Fox Dollar', ` (monospace stacks excepted); keep that prefix on new font stacks. The glyph is traced from `assets-src/brand/fox-dollar-source.jpg` by `scripts/brand/build-fox-dollar.py` (writes `public/fonts/fox-dollar.woff2`, `public/images/fox-dollar.svg` and `public/fox-dollar.js` from `scripts/brand/fox-dollar.template.js`); rerun it after changing either, never hand-edit the outputs.
- `src/lib/use-mobile-full-play.ts`: mobile full screen for the play frame. On phones and touch tablets (`MOBILE_FULL_QUERY`) the modules in `MOBILE_FULL_MODULES` (Short Track Showdown, Darts, Sun Vault, Beanstalk Bounty, Mo' Dollaz) cover the whole screen on their own (`.play-frame.is-mobile-full`), and every other module gets a "Full screen" button in the frame bar that does the same (a module without the handshake keeps the site's close button); the module side is `modules-src/_shared/embed-full.js` (`tl-full-hello` → `{type:'tl-full', on}` → `tl-full-ack`; its `.tl-full-only` "Exit full screen" buttons post `tl-exit-full`, and the frame bar then offers "Full screen" to go back). Until the module acknowledges, the site shows its own close button. Short Track Showdown also shows thumb controls on touch screens (left pad steer left/right, right pad gas and brake/reverse, plus CAM and pause buttons).
- `src/lib/modules.ts`: module catalog (titles, subjects, thumbnails in `public/images/modules/`). `src/components/ModuleHub.tsx`: the homepage library. `mobile: true` on a catalog entry marks a module that plays well on a phone by touch alone (every action needed to play works by touch and the page fits a phone; mark one only after checking its code). It gets a "Mobile friendly" badge on its hub card (`.module-mobile`) and a phone marker in the sidebar (`.nav-mobile`, `ModuleNav.tsx`), and the hub filters get a "Mobile friendly" chip. Phone-sized touch screens (`PHONE_TOUCH_QUERY` in `src/lib/use-media-query.ts`) open the hub on that chip until the visitor picks another, with All one tap away. On phones the hub shows two compact cards per row, and the random picks and filter chips become swipeable rows.
- Chat: `GroupChat` component (src/components/GroupChat.tsx), shown at the right end of the site ribbon, polls `/api/group-chat` (D1 `chat_messages` + `chat_presence`, migrations 0002–0003). `thread` NULL = everyone; otherwise the sorted comma list of member usernames (private chat, up to 8). Presence comes from these polls, not Railway: each poll sends the page's module (`activity`) and `active=1` when the tab is visible, focused and touched in the last 5 minutes (a focused module iframe counts), and `src/server/chat-presence.ts` keeps `chat_presence` plus `chat_activity` (migration 0039, also created on first use: when the user was last active and since when they have been in the current module). Polls return `online` (seen in the last 45 s) and `recent` (the 60 latest in two weeks) with `lastSeen`, `activeAt` and `since`, plus the server clock `now`; `src/lib/chat-presence.ts` turns them into "Active now / Idle 6m / Active 2h ago" and "In Fox Plains · 25m" on the People tab, private chat rows and thread headers. Read receipts: viewing a thread posts `{action:'read', thread, id}` to `/api/group-chat` (table `chat_reads`, migration 0005, also created on first use); polls return other members' read marks and your latest message shows Sent / Seen / Seen by. Minimized, the chat is a small pill at the bottom right (Chat · n online); open, it is a 320 × 440 panel with Chats and People tabs. Clicking anywhere outside it minimizes it, including clicks inside a module iframe (same-origin frames get a pointerdown listener; a window blur into a frame covers the rest), and Escape or the minimize button returns focus to the element or iframe that had it. The chat never takes focus on its own: mousedown on its buttons is prevented so a module keeps the keyboard until the player clicks the message box, and key events inside the chat stop at its root. Signed-out visitors get the online number from the public `GET /api/group-chat?count`. Deleting: anyone removes their own messages (admins any message); the trash button in a thread header deletes a whole private chat for everyone in it (`clear`; any member) or, for admins only, clears the Everyone chat. Deletions are logged for a day in D1 `chat_removals` (migration 0045, also created on first use) and returned as `removed` on each poll so other open tabs drop those messages too. Invites: `meta.invite` {module,label,code}. Embedded modules with online rooms (sandlot, chess, checkers, shorttrack, party, angler, bushleague, rackreel, pingpong, darts) answer `postMessage({type:'tl-host'})` with `{type:'tl-room', code}` and auto-join from `?room=`. No popups or sounds: while anything is unread the minimized pill flashes between red and the accent color and reads "You have a new message!" with the sender (clicking it opens that thread), an open panel shows the same line above other threads, and the browser tab icon blinks a red dot (`src/lib/use-blinking-favicon.ts`), even with reduced motion on, until the messages are read.
- Themes: midnight / slate (label Gray) / light / wics (WICS: the light theme with a #DDDDDD sidebar under a white logo area, a #E0E2D8 gradient header over a 48px #6F83B5 bar, a #D7D6CB page and white score boards). Hub, sidebar and chat colors come from `--lib-*` variables per theme in styles.css; old theme ids map to these in site-themes.ts.
- Record resets: each high-score board registers its currently selected tab with `useRecordResetTarget` (`src/components/AdminRecordReset.tsx`). Only the admin sees the reset button, rendered at the very bottom right of every page by `AdminRecordResetButton`; it clears just the selected board. Reset endpoints accept the admin session (the old reset password still works server-side).
