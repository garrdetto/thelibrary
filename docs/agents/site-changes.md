# Site changes (admin asks Claude to change the site)

The admin chat that runs Claude Code in GitHub Actions or on the laptop. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- `src/server/routes/site-changes.ts`: `/api/site-changes` (admin chat with Claude that edits and publishes the site; see Site changes below).
- `src/components/SiteChanges.tsx` is a chat with Claude. Each admin message becomes a row in D1 `site_changes` (migration 0009, also created on first use) and `/api/site-changes` (`src/server/routes/site-changes.ts`) starts `.github/workflows/site-change.yml` through the GitHub API (`workflow_dispatch` with `job_id` and `callback_url`).
- The workflow runs `.github/site-changes/run.mjs`: it fetches the job and earlier turns from `/api/site-changes?job=` (Bearer `SITE_CHANGES_SECRET`), runs Claude Code headless with the request (every tool, including any shell command; `GH_TOKEN` is `CLAUDE_GITHUB_TOKEN` or the workflow token and reaches git through a `GIT_CONFIG_*` credential helper, nothing saved to disk, so Claude can fetch, fix, push and merge existing pull requests and read checks and run logs; afterwards `publish` returns the checkout to the starting commit before publishing any uncommitted edits), reports progress back, then builds (`pnpm build`), commits to a `site-change/<job>` branch and opens a pull request. With auto-publish it turns on squash auto-merge through the GraphQL mutation (never `gh pr merge --auto`, which merges at once, before any check, when nothing blocks the pull request) and waits for the `modules` check, reporting the squash commit on `main`; when GitHub refuses auto-merge because no branch rule on `main` requires the check, the run watches `modules` itself and merges once it passes. Without auto-publish the pull request waits for review. The publish step uses the `CLAUDE_GITHUB_TOKEN` repository secret when present, because pull requests opened with the built-in token never trigger the check. New migrations are applied when Cloudflare secrets exist. Runs are not serialized: the workflow's concurrency group is per job (`site-change-<job_id>`), so several messages run at once on GitHub's machines (on the laptop they queue for its runner, one at a time per registered runner), and the admin can send another message in a conversation while one is still running (only deleting a conversation waits). Parallel runs each open their own `site-change/<job>` pull request; one that conflicts with another merged first has to be retried. Undo runs `git revert` on the change's commit.
- Meshy: before starting Claude, `run.mjs` mints that job-scoped pass and gives Claude only `SITE_URL` and `SITE_MESHY_TOKEN` (never `SITE_CHANGES_SECRET`); `.github/site-changes/meshy.mjs` (`balance`, `generate "<prompt>" --out <file>.glb [--target character] [--preview] [--polycount N] [--texture ...]`, `animations "<words>"` (Meshy's ready-made library through `/api/meshy?animations=`), `rig <jobId> --out`, `animate <rigJobId> --action <id> --out`) generates through the live site's `/api/meshy`, so runs use the Cloudflare `MESHY_API_KEY` (the same key as the admin generators) and their models appear in the admin Meshy panel. No GitHub copy of the key is needed. Claude may also run `blender` (allowed in `run.mjs`'s `TOOLS`); only the laptop runner has it installed (`scripts/laptop-runner/install-blender.sh` in WSL, see `scripts/laptop-runner/README.md`).
- Credits: Anthropic has no API for a prepaid balance, so the admin enters the balance and the panel subtracts each run's reported `total_cost_usd`. With `ANTHROPIC_ADMIN_KEY` set, it also shows the organization's month-to-date spend from the Admin cost report (cached 5 minutes in `site_change_settings`).
- Run on my laptop: the composer's checkbox (saved as `site_change_settings` key `runner`, `github` or `laptop`) passes the `runner` input to the workflow, whose `runs-on` becomes the self-hosted label (`SITE_CHANGES_RUNNER_LABEL`, default `msi-laptop`) instead of `ubuntu-latest`. Each row records where it ran in `site_changes.runner` (added on first use). When the token can list runners (Administration: Read), the Worker checks the laptop is online and falls back to GitHub with a notice if not. On the laptop the workflow blanks the API key and subscription token secrets and sets `SITE_CHANGES_LOCAL_LOGIN=1`, so Claude Code uses the Claude account signed in there (`run.mjs` reports billing `subscription`). The laptop runner is set up with `scripts/laptop-runner/` (WSL Ubuntu), including Blender (`install-blender.sh`).
- 3D models from a prompt (`docs/MESHY-PIPELINE.md`): the workflow passes the `MESHY_API_KEY` repository secret and the `MESHY_MAX_CREDITS` variable (default 150) to Claude, and when that secret is set `run.mjs` tells it to use `scripts/meshy-generate.mjs` (without it, Claude generates with `.github/site-changes/meshy.mjs` above and runs `scripts/blender/meshy-cleanup.py` itself when Blender is installed) (Meshy text-to-3D preview → refine → rig → animate with library clips, then `scripts/blender/meshy-cleanup.py` when Blender is installed, or `scripts/blender/bushleague/cleanup.py` under `assets-src/models/bushleague/`) into `assets-src/models/`, then `pnpm assets` and the module code. Each model keeps a `<name>.meshy.json` record (prompt, settings, task ids, credits) beside it; reruns resume from it, raw downloads go to the git-ignored `.meshy-cache/`, and clips are renamed to their short names. Only humanoid characters are rigged; everything else is animated in code. `scripts/meshy-mock.mjs` stands in for Meshy, rigging and animation included.
- Stuck jobs: the runner trims and drops empty fields in its reports and, if the site rejects a final report, resends a minimal one; the server tolerates nulls and trims long text. When the panel or a new message checks a conversation, `reconcile` in `site-changes.ts` looks up any job that has been quiet for 3 minutes (at most once a minute per job): a merged pull request marks it `merged`, a finished or cancelled run marks it `review` or `failed`, a run that never started is failed after 30 minutes (6 hours on the laptop), and anything silent for 3 hours stops waiting. This needs the token to read Actions and, for the merged check, Pull requests.
- Worker secrets: `SITE_CHANGES_GITHUB_TOKEN` (fine-grained token, Actions read/write on the repo), `SITE_CHANGES_SECRET`, optional `ANTHROPIC_ADMIN_KEY`, optional `SITE_CHANGES_REPO` (default `garrdetto/thelibrary`). Repository secrets: `SITE_CHANGES_SECRET`, and `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`; optional `MESHY_API_KEY` (3D models) and repository variable `MESHY_MAX_CREDITS`; optional `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` for migrations; optional repository variable `SITE_CHANGES_MODEL` (overrides the model; `run.mjs` defaults to `claude-opus-5-5`).
