# Admin console and tools

The admin console, Meshy panel, image editor and clipart generator. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- `src/components/PoolAccount.tsx`: sign-in form. Signed-out visitors see only `src/components/SignInGate.tsx` (a full-page sign-in / create-account card, `.signin-gate` styles): `src/routes/index.tsx` renders nothing else until `/api/workspace-access` returns a username. `src/components/AdminPanel.tsx`: the admin console, a grouped side nav (deep-linkable as `#admin/<section>`) split by a switch into two areas, Site (Overview and Site changes under Dashboard, Module order, Studios (AI Chat, Image Studio, Lyric Studio, Voice Generator), People; for the admin account only, the sidebar hides the studios and `src/routes/index.tsx` renders each studio page inside the console (`AdminPanel` with `studio` and the page as children, hash `#admin/chat|image|lyrics`), while other granted users keep them in the sidebar) and Module settings (Fox Plains, Short Track Showdown incl. Handling, Darts (`src/components/darts/DartsSettings.tsx`, `#admin/darts`), Bush League Baseball, Thrill Park, and last the Life Sim World editor so opening Module settings starts on Life Sim Vehicles, not the editor), with Overview (`src/components/admin/AdminOverview.tsx`: counts and shortcuts), Module order (`src/components/admin/LibraryArrange.tsx`: drag, arrow-key or button reordering, hide/show and the featured pick; its Top 5 & categories tab (`src/components/admin/LibraryCategories.tsx`) picks the sidebar's Top 5 (empty slots fill from the library order) and edits the categories (add, rename, reorder, remove) and which categories each module is in (several allowed; none means Other); the sidebar shows Top 5 then one drop-down per category (`src/components/ModuleNav.tsx`) and the homepage has All / By category / per-category sort buttons; defaults are `defaultCategories` in `src/lib/module-layout.ts`; all published to `/api/module-layout` (`src/server/routes/module-layout.ts`, D1 `library_settings` key `module-layout`, migration 0017, also created on first use); `src/lib/module-layout.ts` normalizes and applies it and `src/lib/use-module-layout.ts` shares it with `ModuleHub` and the sidebar), People & permissions (`WorkspaceAdmin.tsx`, with search and filters; each person's page has a Slot balance group to add money to their shared slot wallet, see `docs/agents/modules/slots.md`), Site changes (`SiteChanges.tsx`), Image editor (`#admin/image-editor`, `src/components/admin/ImageEditor.tsx` + `ImageEditorStage.tsx`, lazy-loaded: bulk upload, drop or paste; drag or arrow-key a rectangle over text, then Remove text, Smart edit (rewrite it) or AI fill; `src/lib/image-editor-canvas.ts` crops the area around the selection to one of Gemini's aspect ratios (`planContext` in `src/lib/image-editor.ts`), and pastes back only the selected pixels with a short feathered edge and a colour match from the ring around it, so the rest of the picture is unchanged; per-image undo, carry-over selection and Run on all; Save names files `<name><n>.<ext>` with n going up per save and back to 1 for a new name (per-name counters in browser storage as a convenience), as downloads or into a chosen folder via the File System Access API without overwriting; images stay in the browser and nothing is stored on the server), Fox Plains items (`src/components/maplestreet/MapleStreetItemEditor.tsx`) and Life Sim vehicles (`#admin/vehicles`, `src/components/maplestreet/vehicle/VehicleEditor.tsx`; everything published there is for Life Sim only and is tuned in Life Sim's F8 panel), both lazy-loaded and kept out of the Worker bundle. The vehicle editor (`VehicleStage.tsx`: 1 m grid, resident figure, true-scale built-in outlines from `BODY_EXTENTS`, draggable axle/seat/light/hitch markers, paint picking; `draft.ts`: templates, sizing and the publish spec; `modelTools.ts`: browser-side baked-wheel removal, polygon reduction, texture resizing and meshopt compression with `@gltf-transform/*` and `meshoptimizer`; `TestDrive.tsx`: embeds `?vehicleTest=1`; the Your vehicles list's Edit button downloads a vehicle's model and reopens it in the editor (`draftFromRecord` in `draft.ts` inverts the published spec) so saving writes over the same id; the Body step smooths the body (`BodySmoothPanel.tsx` with `useBodySmoothing`, shared with the race car editor): Auto smooth measures every panel, selects the rough areas weighted by how rough they are and previews an edge-keeping clean-up; Scan the body marks bumps deeper than a chosen depth (millimetres as if the model were a full-size car) as yellow-to-red dots and can select them; selections can also be a polygon lasso (`DentSmoother.tsx`, camera-facing vertices, feathered at the edge), the whole body, grown or shrunk a ring at a time; three methods (`smoothAlgorithms.ts`: Clean surface, bilateral normal filtering that keeps creases; Even out, Taubin smoothing that doesn't shrink; Fill dents, over-relaxation for wide dents), every one moving points only along a neighbour-averaged surface normal (`guideNormals`, `push`) so nothing slides across the surface and drags the texture; texture clean-up (`textureSmooth.ts`): Remove painted-on bumps drops the materials' normal and bump maps, Soften blotchy paint runs an edge-keeping (bilateral) blur over the colour textures, both undoable with strength, passes and a crease angle; Smooth shading re-shades the whole body with crease-aware normals (`meshTopology.ts`: welded clusters, face lists, boundaries, `writeVertexNormals`); a hold-to-compare button, keep, clear and undo (12 steps, positions and normals); `bodySmooth.ts` (`BodySmoother`) holds the state, and `exportScene` bakes the result into the .glb that is shrunk and saved; Suggest points: `suggest.ts` finds each axle's position, wheel radius, tire width and track from the model's surface in the ground frame, searching the front and rear halves separately so floating mower casters work, and `suggestRender.ts` collects the triangles and renders side/top/front/rear orthographic views for `/api/maplestreet-suggest`, which also proposes door, hood and trunk boxes; the Seat & lights step marks those boxes as `parts`, published in the spec and cut into opening leaves in the game by `modules-src/maplestreet/src/physics/CutParts.ts`; the same step switches the game's own glowing headlights and taillights on or off (`headOn`/`tailOn`; off publishes empty `lights.head`/`lights.tail`, so only the model's own lamps show) and traces them on a straight-on render of the model (`LampTracer.tsx`, `renderView` in `suggestRender.ts`): the outline becomes the lamp shape, its size `lampShapes.headSize`/`tailSize` (metres, used by `lampTriangles`), the body's surface under it is sampled into `headDepth`/`tailDepth` (a `LAMP_GRID`² grid of forward offsets) so the lens is a thin curved shell following the body instead of a flat plate, and the marker moves to the surface at its centre) The Short Track race car editor (`#admin/shorttrack-cars`, `src/components/shorttrack/cars/CarEditor.tsx`, lazy-loaded) reuses the vehicle editor's pieces (Meshy panel with target `racecar`, dent smoothing, `modelTools.ts` shrinking and baked-wheel removal, `suggest.ts` axle finding and the AI tail-light suggestion) on its own stage (`CarStage.tsx`: stock car outline from `STOCK_CAR`, draggable axle, number-spot and tail-light markers, numbers laid on the body by `numberAnchors`) and draft (`carDraft.ts`: `newCarDraft`, `carSpec`, `draftFromCar`); drafts appear only in the admin's Short Track vehicle list, so the admin can race one before publishing. The Thrill Park Ride creator (`#admin/park-rides`, `src/components/park/rides/RideCreator.tsx`, lazy-loaded) has the Meshy panel with target `ride`, .glb upload, and a React Three Fiber stage (`RideStage.tsx`) that runs the ride's real load/ride cycle with the shared `motionMatrix`; `bake.ts` merges the model's meshes into park axes, simplifies with meshoptimizer to the triangle budget, samples base colour textures into one sRGB colour per triangle corner, then fits it to the footprint and splits the moving part; `suggest.ts` proposes prices and ratings by distance-weighted nearest neighbours over the built-in rides (category, footprint, height, motion). and both editors include `MeshyPanel.tsx` (Generate with Meshy; client calls in `src/lib/meshy-client.ts`). The item and vehicle editors are the only React Three Fiber code on the site (`@react-three/fiber` 9.8.2, `@react-three/drei` 10.7.9): `DevModeCanvas.tsx` holds the editor context and canvas (1 m grid, footprint outline), and `EditableModel.tsx` loads the picked file through `URL.createObjectURL` + `useGLTF` and attaches `TransformControls` in scale mode, tracking `{x,y,z}` in state. Client calls are in `src/lib/maplestreet-items.ts`.
- `src/server/routes/meshy.ts` + `src/server/meshy.ts`: `/api/meshy`, admin only. Calls Meshy's REST API with the `MESHY_API_KEY` secret (never sent to the browser; Meshy errors are mapped to plain messages). `?status` returns connected, balance and the credit table (`src/lib/meshy.ts`); GET lists jobs and refreshes unfinished ones; POST actions `text` (previews), `image`, `refine`, `remesh`, `retexture`, `rig` (rigs a finished textured job at a height), `animate` (a finished rig plus a Meshy animation action id), `cancel` (deletes the task; Meshy doesn't refund started tasks), `hide` (removes it from the list but keeps the row and stored model), `delete` (admin session only, never a site-change pass: deletes a still-running task at Meshy like `cancel`, then the `meshy_jobs` row and KV `meshy-model/<jobId>`, clearing `parent_id` on jobs made from it; refused while the site-change run that created the job is still queued or running; published items, vehicles, cars and rides keep their own copies, and park rides' `source_job` is only a record). The Meshy panel (`src/components/maplestreet/MeshyPanel.tsx`) has a confirmed Delete beside "Remove from list" on every job. Jobs are in D1 `meshy_jobs` (migration 0015); finished models are stored in KV `meshy-model/<jobId>` and served by `?model=<jobId>`. `MESHY_API_BASE` (dev only) points at `scripts/meshy-mock.mjs`. Site-change runs may also use it without a session: `src/server/site-change-token.ts` accepts `Bearer sc.<jobId>.<HMAC-SHA256(SITE_CHANGES_SECRET, "meshy:<jobId>")>` only while that `site_changes` row is queued or running (same-origin is skipped for it, and jobs are recorded as created by `site-change:<jobId>`).
- `src/server/routes/image-editor.ts`: `/api/image-editor`, admin only, POST (same-origin, Zod) `{mode: remove|edit|fill, prompt, image, guide, aspect, size}`: `image` is the area around a selection, `guide` the same crop with the selection outlined in magenta and the rest darkened; sends both to Gemini (`IMAGE_MODEL`) with the requested aspect ratio and returns the edited crop as a data URL. Stores nothing.
- `src/server/routes/clipart.ts` + `src/server/clipart.ts`: `/api/clipart`, the admin HD clipart generator (image-to-image, admin only). Engines (`ENGINES` in `src/lib/clipart.ts`): FLUX.2 klein 9B and 4B (`@cf/black-forest-labs/flux-2-klein-*`, multipart with the photo as `input_image_0` and an optional style reference as `input_image_1`, inputs under 512 px) on the free Cloudflare Workers AI allowance through the `AI` binding (`"ai"` in `wrangler.jsonc`), plus Gemini (`IMAGE_MODEL`, the site's key, billed; a free-tier key has no image quota and comes back as `limit: 'quota'`). Stable Diffusion was removed: Cloudflare blocks it and retires every SD model on 2026-11-20. Workers AI error 3030 means Cloudflare's output safety filter flagged that photo's result (422). Every slider in `CLIPART_SLIDERS` goes into the prompt (`buildPrompt`/`sliderInstruction`), presets are `CLIPART_PRESETS`. A preset's `finish` is `clipart` or `photo`: the photo finish (Defined Textured Photo) keeps a real photograph with sharper definition and texture, drops the Clipart style group and Photographic realism (`visibleSliders`), and adds a tiny `settings.clipartTouch` strength (0–10%, `CLIPART_TOUCH_LEVELS`). GET (admin) returns each engine's `ready`/`reason` and the saved presets (D1 `library_settings` key `clipart-presets`); `?image=<id>` serves a result; `?jobs=1` lists recent jobs. POST (same-origin, Zod) `generate` stores the result in KV `clipart/<id>` (30-day TTL) and a row in D1 `clipart_jobs` (migration 0037, also created on first use; failures are recorded too) and returns the size the engine actually returned (read from the image header); `save-preset`, `delete-preset`. Workers AI daily-allowance errors come back as 429 `limit: 'quota'` (the page pauses the queue), busy/rate-limit errors as 429 `limit: 'busy'` with `retryAfter` (the page retries with backoff). The page is `src/components/admin/ClipartGenerator.tsx` with `ClipartControls.tsx` and `ClipartPreview.tsx` (Admin → Tools → Clipart generator, `#admin/clipart`): bulk upload, per-engine concurrency queue with pause, resume, cancel and retry, side-by-side and slider comparison, zoom, full screen, and PNG/JPEG/WebP export or a ZIP (`src/lib/zip.ts`); export conversion is the only canvas step, generation is always the engine's.
