# Straight Rail Setup Lab

Chassis setup and suspension-geometry module (module id `railsetup`, `modules-src/railsetup/`, page `/modules/railsetup.html`, catalog card in `src/lib/modules.ts` with `public/images/modules/railsetup.webp`). It is the owner's Windows app StraightRailSetupLab.exe (version 1), a Go launcher that served an embedded web page in an Edge window, running in the browser as a 1:1 copy: the page, its math and its 70 MB model are the exe's own files, unchanged. The owner holds all rights to it. Keep this file current when the module changes.

## The original, unchanged

- `original/` holds the page (`index.html`, CRLF line endings), `kin.js`, `lib/fonts.css`, the six woff2 fonts and `version.txt`, extracted byte for byte from the exe by `node modules-src/railsetup/tools/extract-exe.mjs <StraightRailSetupLab.exe>` (it reads the Go `embed.FS` without running the exe). `original/MANIFEST.json` records the size and SHA-256 of every file the exe carried. Never edit anything in `original/`; to take a new version of the app, rerun the extractor and re-record the fixtures.
- three.js r128, its `GLTFLoader.js` and `OrbitControls.js` are the npm package `three@0.128.0`, pinned in `package.json` as `three-r128` and byte-identical to the exe's copies (checked by `tests/original.test.ts`). The site's own three.js (0.186) is not used here, because the original's lighting, materials and color handling are r128's.
- car.glb (70,447,244 bytes, 143 parts, 2,792,374 triangles, no simplification) is stored as gzip pieces in `original/car/` because Cloudflare caps one static file at 25 MiB.
- Owner exceptions to site rules, for the 1:1 copy: the original's materials (metalness 0.2–0.4, roughness 0.5–0.6) are kept instead of the gloss rule; the original renders at 2–3× pixel ratio from the start with no Graphics setting; the model's internal part names (one is a rear-end maker's name) are kept, and none of them is shown on screen.

## How the page is served

- `tools/original-page.ts` is a Vite plugin (`railsetupOriginal()`, registered in `vite.modules.ts`). It writes `railsetup.html` as `original/index.html` with exactly four additions: after `<meta charset="utf-8">`, `<base href="/modules/railsetup/">` and the inline car loader `site/pre.js`; after the main `</style>`, the script and stylesheet tags Vite built from `index.html` + `index.ts` (plus `/fox-dollar.js`); at the end, `site/bridge.js`. It emits the original's other files under `/modules/railsetup/` (git-ignored) and the car pieces as `/modules/chunks/railsetup-car-<hash>-<n>.gz` (immutable caching through `public/_headers`).
- `site/pre.js` wraps `fetch` before the original's scripts run: `car.glb` is fetched as the gzip pieces, unpacked with `DecompressionStream` and handed to the original's GLTFLoader as the same bytes (the loading text shows a percentage); the launcher's keep-alive `POST /ping` and `sendBeacon('/bye')` are answered in the page and never reach the network.
- `site/bridge.js` runs after the original's scripts and exposes its state as `window.__rail` (`saved`, `adj`, `radj`, `HP`, `HP0`, `DEF`, `loaded`, `SETUP_EL`, `snapshot`, `fillLists`, `useHardpoints`, and replacing `writeSaved` / `useHardpoints`). `site/page.ts` types it (`RailPage`).

## What the site adds (`index.ts`, `site/`, `site.css`)

- Access: private module. `privateModuleIds` in `src/lib/module-layout.ts` keeps it in `hidden` for everyone; `/api/module-layout` drops it for administrators and people granted `module:railsetup`. Its own page is `/railsetup` (`src/routes/railsetup.tsx`): a full-window iframe of `/modules/railsetup.html?page=1` with a "Return to Homepage" tab; `?page=1` adds `rs-page`, which lifts `.stats` and pads `.wrap` clear of the tab. The site ribbon shows a Straight Rail tab next to Axiom Radar for anyone who can see the module.
- `site/app.ts` (`startSite`): ▶ Test on track in the view bar (`#v-track`) and under Corner radius in Track (`#tt-open`), Save as Test Drive Baseline (`#tt-base`), Use default baseline (`#tt-base-reset`), the baseline note (`#tt-base-note`), one help line, and the Exit full screen button for the phone play frame (`initEmbedFull`).
- `site/account.ts` (`useAccount`): saved setups and the loaded hardpoints file live in the account, not the browser. Signed in, the list comes from `/api/railsetup` (`src/server/routes/railsetup.ts`, tables `railsetup_setups`, `railsetup_hardpoints`, migration `0052_railsetup.sql`; GET `{signedIn, setups, hardpoints}`, POST `save`, `delete`, `hardpoints`, `clear-hardpoints`, same-origin) and every change the original's Save, Delete or Import writes is synced; the note under Saved setups reads "Saved to your account." (`#sv-where`, replacing the original's "Saved on this computer."). Names longer than 60 characters (the account's limit) stay on the page with a notice. Signed out, setups last until the page closes. "Back to the straight rail chassis" clears the account's hardpoints file. The original still keeps its view preferences (help seen, folded sections) in localStorage.
- `site.css`: Test on track styles, the overlay, `rs-page`, and phone sizing at 860 px and narrower (taller touch targets, 16 px inputs, sticky tabs, a 48vh view, the view buttons above the tire tags, compact view buttons at 600 px and narrower). Desktop layout is the original's.

## Test on track (Short Track Showdown)

- `ui/track-test.ts` (`TrackTest`) opens a full-page overlay with Short Track Showdown's track test (`/modules/shorttrack.html?lab=1&rad=<Corner radius>&bank=<Banking>`, see `docs/agents/modules/shorttrack.md`). The page says `rail-test-ready`; the Lab answers `{type: 'rail-setup', vehicle, name}` (name: the Saved setups name field, else the selected saved setup, else "Current setup"). The overlay stays loaded while hidden; reopening sends the setup again only when it changed, and a new radius or banking reloads it. `rail-test-close` or Escape hides it.
- The car on track is computed by the renderer-free port of the original's math (`sim/`), from the page as it stands: `labFromPage` → `readPage` (hardpoints as they stand, the page's own defaults for empty boxes, every setup input, front and rear adjustments, the fixed-MR switch, the Heave/Roll/Steer view sliders) → `labFromState`. `railVehicle(lab, name)` solves it at rest on `lab.copy()` with Lateral g, Long g, Banking and the view sliders at zero.
- Test drive baseline: an ordinary saved setup named `Test Drive Baseline` (so it goes to the account); Use default baseline removes it and the baseline becomes the page's defaults. `TrackTest.handling()` sends `vehicle.handling`: `railHandling` solves the grip balance at the three `HANDLING_PHASES` for the setup and the baseline, and `handlingDelta` is the difference (+ tighter, − looser).

## Calculations (`sim/`, renderer-free and deterministic)

- `sim/kin.ts`: typed port of the original's `kin.js` (identical results). `rearResidual` says how far a rear pose misses the link lengths; `rearPoseNear` is kept for `tests/isolation.test.ts`.
- `sim/lab.ts`: class `Lab`, the port of the original's setup model (`calc`, `advSolve`, `rideSet`, motion-ratio tables, plot series). `Lab.defaults` is what an empty or invalid input falls back to (the page's own `DEF` in the track test; `DEFAULTS` otherwise); `Lab.copy()` makes an exact copy (no second seating of a hardpoints file, same defaults); `useHardpoints(hp, name, seat = true)`; `model.settled` is false when the corner solve didn't converge in its 12 passes.
- `sim/hardpoints.ts` (`CAD`, `reseat`, `END_LINKS`, `parseHardpoints`), `sim/inputs.ts` (`SETUP_INPUTS` with the original's ids, `APP_DEFAULTS` = the original page's defaults, `SLM_BASELINE`, `withDefaults`, `ADJ0`, `RADJ0`, `SLUGS`), `sim/files.ts` (setup files in the original's export shape), `sim/vehicle.ts` (`railVehicle`, `railHandling`, `handlingDelta`, `railTrackQuery`).

## Model for Short Track's chassis view

Short Track's Show chassis view (`shorttrack/rail-cutaway.ts`) uses a light copy, `public/models/railsetup/chassis.glb` (2.5 MB), built by `pnpm assets` from `assets-src/models/railsetup/chassis.glb`, which `tools/prepare-model.mjs <original car.glb> 0.04 0.001` makes from the exe's model; `ui/parts.ts` loads and poses it. The Setup Lab page itself always shows the full original model.

## Tests

`node scripts/railsetup-tests.mjs` (part of `pnpm test`):
- `tests/original.test.ts`: every original file matches the exe byte for byte (manifest SHA-256), three r128 comes from `three-r128`, the car pieces unpack to the original model (143 meshes, each piece under 25 MiB), removing the four additions from the served page gives the original exactly, and the bridge only names things the original declares.
- `tests/page-parity.test.ts`: replays `tests/fixtures/page-parity.json` (90 states recorded from the original page in Chromium by `tools/capture-page-parity.mjs`: random setups, LF/RF/rear Kinematics moves, slugs, track bar type, fixed MR, Advanced mode, a loaded hardpoints file) through `labFromState` and requires every number of the page's `model` to match within 1e-6 (in practice about 2e-11). States the original can't solve are skipped (Advanced-mode springs that put a ride height outside 1–7 in, a corner solve that never settles, rear links that can't reach); at most a quarter may be skipped. Also checks that `Lab.copy` keeps a hardpoints file as given.
- `tests/account.test.ts`: the account's schemas (`snapshotSchema`, `hardpointsSchema`) keep every input of a setup saved by the original page and its hardpoints exactly.
- `tests/parity.test.ts` (24 single cases with plots, `tests/fixtures/parity.json`, `tools/capture-parity.mjs`), `tests/isolation.test.ts`, `tests/rules.test.ts`, `tests/vehicle.test.ts`, and Short Track's `railHandling.test.ts`, `railCutaway.test.ts`, `rail.test.ts`.
