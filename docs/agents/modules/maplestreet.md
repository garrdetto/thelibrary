# Fox Plains (maplestreet)

The classic Fox Plains town, its admin items and vehicles. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- Fox Plains (`public/modules/maplestreet.html`, module id `maplestreet`) is generated: edit the TypeScript in `modules-src/maplestreet/` (`src/` client, `shared/` rules, `colyseus-server/` optional Node room); `pnpm build` rebuilds it with the other modules. It uses the bundled three.js WebGPU build (WebGL2 fallback) and Rapier 0.14 compat. There is no start screen: the page goes straight into the shared open world under the library username, or a fixed `Guest-xxxxx` for this browser (`?solo=1` still runs solo mode with unlimited money, `unlimitedMoney`). Everyone starts with the bundled Maple Hauler pickup (`STARTER_TRUCK` in `shared/Economy.ts`). Performance: static colliders are streamed around the player (`Physics.stream`), static content is batched per material with plain finishes folded into one vertex-colored node material (`src/core/Merge.ts`), and `Engine.adapt` lowers the pixel ratio only when frames run slow; see the Performance section of `modules-src/maplestreet/README.md`. Characters are made once in the wardrobe panel on arrival (male/female is final); after that clothes only change at Maple Threads (`keepOutfit`, enforced by `RoomLogic`). Lawns store per-cell cut time and blade lean (`shared/Mowing.ts`): grass regrows over five in-game days, stripes are view-dependent lean that fades with growth, and diagonal passes over older stripes make diamond patterns. To reset everyone, bump `WORLD_GENERATION` in `shared/WorldServer.ts` (now `g2:`). `shared/RoomLogic.ts` is the single authority (lot ownership, build validation incl. batched `builds` gestures, money, $50,000 loan cap, mowing pay, deliveries, shops, fuel, needs and home-item use). The default mode is one persistent shared world: `/api/maplestreet` (`src/server/routes/maplestreet.ts`, members by session, guests by a zod-checked key) upgrades to the Durable Object `MapleStreetWorld` (`src/server/maplestreet-world.ts`, binding `MAPLE_WORLD`), which runs `shared/WorldServer.ts` and saves to the D1 table `maplestreet_world`. The same logic also runs in the page for solo play (also the fallback when the world can't be reached) and in the optional, unused Colyseus server. Admin-published Buy items (`shared/CustomItems.ts`, catalog ids `custom:<uuid>`) are registered into `CATALOG` by the Durable Object before it loads the world and by `src/build/CustomModels.ts` before the page starts any mode, so every authority validates and prices them; retired items stay valid but leave the Buy catalog. Vehicles are data-driven the same way: `shared/Vehicles.ts` holds built-in tuning and the `TUNING` registry (`VehicleKind` is a built-in name or `custom:<uuid>`), and admin-published vehicles (`shared/CustomVehicles.ts`, plus the bundled ones in `shared/BundledVehicles.ts` with models in `public/modules/maplestreet/vehicles/`, which every registration includes) are registered by the Durable Object and by `src/physics/CustomVehicleModels.ts` before anything loads; `normalizeAccount` keeps `custom:` garage entries. `shared/VehicleDrive.ts` turns top speed and 0–60 targets into engine numbers that match the physics, and `?vehicleTest=1` (`src/game/VehicleTestDrive.ts`) is the editor's test drive. Town layout (60 grid lots on ten residential streets, plus 20 mixed-size lots up to 60 × 60 m on the curved Willow Bend streets west of West Ave (`CURVES`, `curveDistance`; prices from `lotPrice`), roads, downtown shops, the fire and police stations behind downtown, gas station) is `shared/WorldLayout.ts`, and the downtown grid east of Market Ave (twelve blocks, about 90 scenery buildings, the Maple Commons town square in `src/world/TownSquare.ts`) is `shared/DowntownGrid.ts`; starter houses `shared/Seed.ts` (28 simulated neighbors, upgraded once per `SEED_VERSION` without touching player lots) built from the plans in `shared/HousePlans.ts`; sidewalks `residentialSidewalks()` in `shared/WorldLayout.ts`; the developer instance (`?dev=1`, a private solo save that loads the admin's drafts) `src/core/DevMode.ts`, with its F8 panel `src/game/DevPanel.ts` (for the admin, the site's Developer Panel button above the frame loads `?dev=1&solo=1&panel=1` and then toggles the panel with a same-origin `{type:'tl-dev-panel'}` message); simulated neighbors `shared/Npc.ts`; Sims-style build/buy tools `src/build/BuildController.ts` with the catalog in `shared/Catalog.ts` and models in `src/build/Furniture.ts`; downtown `src/world/Downtown.ts`; instanced grass `src/world/Grass.ts`; HUD, town map and minimap (street route to the current delivery stop) `src/game/Hud.ts`, `src/game/PlotMap.ts` and `src/game/MiniMap.ts`. Each owned car's look is stored per vehicle kind in `Account.cars` (`shared/Cars.ts`: paint color and gloss/metallic/matte finish, filled with the factory paint by `normalizeAccount`); Maple Motors shows a paint picker before buying (`buy` carries `car`), and the authority stamps the owner's `style` onto vehicle snapshots so neighbors see the same paint, while `Vehicle.restyle` and `RemoteEntities` repaint in place when it changes. Published vehicles whose paint mode is `none` aren't `paintable` and skip the picker. Crash damage: `Vehicle` flags a hit when its horizontal velocity changes by more than `CRASH_MIN_DV` (4 m/s) in one physics step (teleports, resets and hitching call `quiet()` first) and the client sends `crash` with the speed change and the struck chassis point; `RoomLogic` applies it only to an owned car the player has out (at most every 400 ms), adding `damage` and a dent (`addCrash`). Damage costs engine power and grip (`conditionEffects`) and dulls the paint, until it's repaired at Maple Body & Wheel (`shared/BodyShop.ts`, building `src/world/BodyShop.ts`, window `src/game/BodyShopUI.ts`): a three-bay garage on Commerce St east of the police station where a player parks an owned car in a bay, walks up and presses E for repairs, paint, window tint (built-in vehicles), rims (`buildStyledWheel`), lift and lowering kits (suspension rest length, bigger tires from +2) and performance parts; the client sends `service` and `RoomLogic` checks the car is in a bay, prices the order with `quote` and applies it to `Account.cars` (`tuneEffects` turns it into engine, top speed, brake, grip, lift and tire-size multipliers that `Vehicle.setCar` applies), dents are pressed into the body mesh by `src/physics/Dents.ts`, and both travel in the snapshot `style` so neighbors see them. New neighbors start with $105,000. Vehicles are original designs; keep brand names and logos out. `modules-src/` is excluded from `tsconfig.json`. Player avatars are the scanned male/female models in `public/modules/maplestreet/` (chosen once in the character creator), recolored by `src/avatar/AvatarMaterial.ts`; the wardrobe (C) and the Maple Threads clothing shop use `shared/Wardrobe.ts`. Details are in `modules-src/maplestreet/README.md`.
- `src/server/routes/maplestreet-items.ts`: `/api/maplestreet-items`, Fox Plains's admin item pipeline. GET lists every published item (public, retired ones included with `active: false` so houses that own them keep them); `?model=<id>` serves the .glb/.gltf from KV `maplestreet-item/<id>` with an immutable cache. POST (admin, multipart: `model` file plus `name`, `price`, `scale` JSON `{x,y,z}`, `room`, `func`, `indoor`, `solid`, `yaw`, `w`, `d`, `h`, optional `status` `draft`/`published`) checks the model with `src/server/gltf-check.ts` (glTF 2.0, ≤ 15 MB, no Draco/Basis, self-contained .gltf), stores it, inserts a row in D1 `maplestreet_assets` (kind `item`; Zod schema `storeItemSchema` in `src/server/maplestreet-items.ts`) and, when published, tells the `MapleStreetWorld` Durable Object to reload the catalog. PATCH (admin, JSON `{id, status?, active?, name?, price?}`) publishes a draft, retires or restores an item. DELETE (admin, JSON `{id}`, `src/server/maplestreet-asset-delete.ts`) removes the row (and its older `maplestreet_items` copy, so the back-fill can't restore it) and the KV model: drafts always; published or retired items only when no saved lot or account in the shared world mentions `custom:<id>` (the Durable Object saves first through its `/save` path, and `worldMentions` in `src/server/maplestreet-world.ts` searches `maplestreet_world`), otherwise it answers 409 asking the admin to retire it; then it refreshes the world catalog. GET lists drafts only to the admin with `?drafts=1` (the response says `drafts: true` when it did).
- `src/server/routes/maplestreet-vehicles.ts`: `/api/maplestreet-vehicles`, published vehicles. The admin vehicle creator is Life Sim's: every POST and PATCH that saves a spec stamps `game: 'lifesim'`, so the vehicle is sold only at Life Sim's dealership (`forLifeSim` / `forFoxPlains` in the shared code; Fox Plains still registers it for owners but never sells it or puts it in traffic). GET lists every vehicle (public, retired ones included with `active: false` so owners keep them); `?model=<id>` and `?wheel=<id>` serve KV `maplestreet-vehicle/<id>` and `maplestreet-vehicle/<id>/wheel`. POST (admin, multipart: `model`, optional `wheel`, `name`, `spec` JSON checked by Zod `vehicleSpecSchema` in `src/server/maplestreet-vehicles.ts`) stores the record in D1 `maplestreet_assets` (kind `vehicle`) and, when published, refreshes the `MapleStreetWorld` catalog; optional `status` `draft`/`published`. PATCH (admin, JSON `{id, status?, active?, name?, spec?}`) publishes, retires, restores or edits. POST with an `id` field (a published uuid or a `bundled-*` id, which gets its override row first) saves a new model, name, spec and status over that vehicle; model URLs carry `&v=<version>` so the immutable cache refreshes. DELETE (admin, JSON `{id}`) removes a vehicle, its older `maplestreet_vehicles` copy and its model and wheel files by the same rules as items (drafts always; published or retired ones only while no saved account or lot mentions `custom:<id>`, otherwise 409 "retire it instead"); built-in `bundled-*` vehicles can't be deleted. PATCH `{id, glass}` (admin, up to 1 MB) saves or, with `null`, removes a vehicle's traced windows (Life Sim's developer panel → Trace windows): `glass` in the spec (`modules-src/maplestreet/shared/VehicleGlass.ts`, Zod `vehicleGlassSchema`: per body mesh its place among the model's meshes, triangle and vertex counts, and the glass triangles as base-36 runs), which pages use instead of the automatic window detection; a bundled id gets its override row first, other PATCH edits keep it, and saving a new model (POST) drops it. GET lists drafts only to the admin with `?drafts=1`. The item and vehicle editors have a confirmed Delete on each row (`src/components/maplestreet/DeleteAssetButton.tsx`).
- `src/server/routes/maplestreet-suggest.ts`: `/api/maplestreet-suggest`, admin only, POST `{kind, views:{side,top,front,rear}}` (JPEG data URLs of orthographic renders). Asks Gemini (`TEXT_MODEL`, JSON schema) for the driver seat, one headlight, one taillight and the hitch as 0–1000 image points and returns them; the vehicle editor turns them into metres.
- `src/server/maplestreet-assets.ts`: D1 `maplestreet_assets` (migration 0016, also created on first use and back-filled from the older `maplestreet_items` and `maplestreet_vehicles` tables with `INSERT OR IGNORE`, which are kept but no longer written). One row per admin-published asset: `kind` (`item`, `vehicle`, and later `garment`, `accessory`, `prop`, `building`), `status` (`draft`, `published`, `retired`; `shared/Assets.ts`), JSON `spec` and `files` (role → KV key, type, bytes). Drafts are visible only to the admin and only in the developer instance (`/modules/maplestreet.html?dev=1`, `src/core/DevMode.ts`), a private solo game with its own save. Names with real makes or models are refused.
