# Fox Plains shared code (maplestreet)

The code left from the retired Fox Plains town that Life Sim, Kestrel County and the admin item and vehicle editors still use. Moved out of AGENTS.md so it loads only when this area is worked on; keep it current here, not in AGENTS.md.

- Fox Plains is retired and no longer built or listed; `#module-maplestreet` redirects to Life Sim. What stays in `modules-src/maplestreet/` is the code other areas import, so the folder keeps its name: `shared/` (the world rules `RoomLogic.ts` and `WorldServer.ts`, run by Life Sim's `FoxLakeWorld` Durable Object; the item catalog `Catalog.ts`/`CustomItems.ts`; vehicles `Vehicles.ts`, `CustomVehicles.ts`, `BundledVehicles.ts`, `VehicleDrive.ts`, `VehicleGlass.ts`, `WindowDetect.ts`, lamps and paint helpers used by the admin vehicle editor; `Economy.ts`, `MontelloPlaces.ts`, `WorldLayout.ts` and friends that `RoomLogic` needs), `src/net/` (`Transport`, `OfflineTransport`, `WorldTransport`, `Host`) and `src/core/` (`Storage`, `Input`, `DevMode`) used by Life Sim and Kestrel County, and `src/avatar/Gait.ts`/`RigData.ts` used through Fox Plains 2's avatar by Kestrel County. Its tests (`tests/`, run by `scripts/maplestreet-tests.mjs` in `pnpm test`) cover only that shared code. Before deleting anything here, check that nothing outside the folder imports it. The `MapleStreetWorld` Durable Object class and its `MAPLE_WORLD` binding stay because `FoxLakeWorld` extends the class and removing a Durable Object class (a `deleted_classes` migration) permanently erases its storage; nothing routes to the Fox Plains world any more (`/api/maplestreet` serves only `?world=foxlake`). The models it still serves are `public/modules/maplestreet/` (bundled vehicles and the avatar models Kestrel County uses) and `public/models/maplestreet/` (vehicles, furniture and the editor's resident figure). Vehicles are original designs; keep brand names and logos out.
- `src/server/routes/maplestreet-items.ts`: `/api/maplestreet-items`, the admin item pipeline for Life Sim's Buy catalog. GET lists every published item (public, retired ones included with `active: false` so houses that own them keep them); `?model=<id>` serves the .glb/.gltf from KV `maplestreet-item/<id>` with an immutable cache. POST (admin, multipart: `model` file plus `name`, `price`, `scale` JSON `{x,y,z}`, `room`, `func`, `indoor`, `solid`, `yaw`, `w`, `d`, `h`, optional `status` `draft`/`published`) checks the model with `src/server/gltf-check.ts` (glTF 2.0, ≤ 15 MB, no Draco/Basis, self-contained .gltf), stores it, inserts a row in D1 `maplestreet_assets` (kind `item`; Zod schema `storeItemSchema` in `src/server/maplestreet-items.ts`) and, when published, tells Life Sim's `FoxLakeWorld` Durable Object to reload the catalog. PATCH (admin, JSON `{id, status?, active?, name?, price?}`) publishes a draft, retires or restores an item. DELETE (admin, JSON `{id}`, `src/server/maplestreet-asset-delete.ts`) removes the row (and its older `maplestreet_items` copy, so the back-fill can't restore it) and the KV model: drafts always; published or retired items only when no saved lot or account in the shared world mentions `custom:<id>` (Life Sim's Durable Object saves first through its `/save` path, and `worldMentions` in `src/server/maplestreet-world.ts` searches `foxlake_world`), otherwise it answers 409 asking the admin to retire it; then it refreshes the world catalog. GET lists drafts only to the admin with `?drafts=1` (the response says `drafts: true` when it did).
- `src/server/routes/maplestreet-vehicles.ts`: `/api/maplestreet-vehicles`, published vehicles. The admin vehicle creator is Life Sim's: every POST and PATCH that saves a spec stamps `game: 'lifesim'`, so the vehicle is sold at Life Sim's dealership (`forLifeSim` in the shared code). GET lists every vehicle (public, retired ones included with `active: false` so owners keep them); `?model=<id>` and `?wheel=<id>` serve KV `maplestreet-vehicle/<id>` and `maplestreet-vehicle/<id>/wheel`. POST (admin, multipart: `model`, optional `wheel`, `name`, `spec` JSON checked by Zod `vehicleSpecSchema` in `src/server/maplestreet-vehicles.ts`) stores the record in D1 `maplestreet_assets` (kind `vehicle`) and, when published, refreshes Life Sim's world catalog; optional `status` `draft`/`published`. PATCH (admin, JSON `{id, status?, active?, name?, spec?}`) publishes, retires, restores or edits. POST with an `id` field (a published uuid or a `bundled-*` id, which gets its override row first) saves a new model, name, spec and status over that vehicle; model URLs carry `&v=<version>` so the immutable cache refreshes. DELETE (admin, JSON `{id}`) removes a vehicle, its older `maplestreet_vehicles` copy and its model and wheel files by the same rules as items (drafts always; published or retired ones only while no saved account or lot mentions `custom:<id>`, otherwise 409 "retire it instead"); built-in `bundled-*` vehicles can't be deleted. PATCH `{id, glass}` (admin, up to 1 MB) saves or, with `null`, removes a vehicle's traced windows (Life Sim's developer panel → Trace windows): `glass` in the spec (`modules-src/maplestreet/shared/VehicleGlass.ts`, Zod `vehicleGlassSchema`: per body mesh its place among the model's meshes, triangle and vertex counts, and the glass triangles as base-36 runs), which pages use instead of the automatic window detection; a bundled id gets its override row first, other PATCH edits keep it, and saving a new model (POST) drops it. GET lists drafts only to the admin with `?drafts=1`. The item and vehicle editors have a confirmed Delete on each row (`src/components/maplestreet/DeleteAssetButton.tsx`).
- `src/server/routes/maplestreet-suggest.ts`: `/api/maplestreet-suggest`, admin only, POST `{kind, views:{side,top,front,rear}}` (JPEG data URLs of orthographic renders). Asks Gemini (`TEXT_MODEL`, JSON schema) for the driver seat, one headlight, one taillight and the hitch as 0–1000 image points and returns them; the vehicle editor turns them into metres.
- `src/server/maplestreet-assets.ts`: D1 `maplestreet_assets` (migration 0016, also created on first use and back-filled from the older `maplestreet_items` and `maplestreet_vehicles` tables with `INSERT OR IGNORE`, which are kept but no longer written). One row per admin-published asset: `kind` (`item`, `vehicle`, and later `garment`, `accessory`, `prop`, `building`), `status` (`draft`, `published`, `retired`; `shared/Assets.ts`), JSON `spec` and `files` (role → KV key, type, bytes). Drafts are visible only to the admin, in the editors. Names with real makes or models are refused.
