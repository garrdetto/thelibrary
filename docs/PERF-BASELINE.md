# Performance baseline

Measured 2026-11-05 by `node scripts/perf-baseline.mjs` against `pnpm dev` (commit `fe64ab2`).
Headless Playwright Chromium 153.0.8010.12, software WebGL (SwiftShader), viewport 1280×800, cache disabled, one fresh context per module.
Each module is opened from the hub as a visitor would, left for 3 s, then every animation frame is recorded for 5 s.

These are the numbers every later phase must beat. Re-measure with `node scripts/perf-baseline.mjs --compare` on the same machine class; absolute FPS under software WebGL is far below a real GPU, so compare runs, not machines.

Bush League Baseball (Phase 2: broadcast lighting, crowd, grass and post on the auto tier, which is `medium` under software WebGL) was measured on 2026-11-06 with the same probe, warm-up and sample window but opened standalone (`/modules/bushleague.html` from a production module build, Edge 156 with software WebGL) rather than through the hub on `pnpm dev`, so its transferred and JS sizes are minified and not comparable with the rows above; re-run `node scripts/perf-baseline.mjs --only bushleague` from a working `pnpm dev` to replace it. The Phase 1 gray box measured 2.7 fps, 38 three.js draws and 110 GPU draws the same way; software rendering says nothing about the real-GPU budget (60 fps at 1440p ultra on an RTX 3060-class card), which still has to be checked on hardware.

Short Track Showdown classic reference for `docs/shorttrack/PLAN.md` (Phase 1, 2026-11-06): the same probe against a production build in `vite preview` (workerd) on port 4173, Edge headless with software WebGL, menu screen: first frame 3,080 ms, 0.2 fps, 17.4 MB heap, 1 three.js draw, 188 GPU draws per frame, 5,600 KB transferred. The row above (459 GPU draws per frame on `pnpm dev`) stays the draw-call budget for the Phase 2 Babylon renderer. Phase 2 (`?engine=next`, Babylon drawing the classic scene graph) measured with the GPU draw calls counted per frame in headless Edge on an RTX 4060 Laptop GPU: menu 196 (classic 207 the same way), mid-race with 20 cars, shadows and the mirror 668 (classic 800), identical on WebGPU and WebGL2. Phase 3 tiers, live 20-car race in the same headless Edge (classic 24 fps there): WebGPU low 29, medium 17.5, high 11.5, ultra 10 fps; WebGL2 medium 25.5, high 5.9 fps. The headless harness throttles every engine, so the 60 fps medium target is for a visible browser on real hardware.

## Columns

- First frame: milliseconds from opening the module (hub navigation, or the hub-card click for pool) to its first WebGL/WebGPU draw call; `(canvas2d)` marks the first 2D canvas draw and `(fcp)` the iframe first contentful paint for embedded modules that draw neither. `—` means the landing screen draws no canvas (for example a sign-in prompt or menu).
- Avg FPS: frames recorded divided by the sample window. 1% low FPS: 1000 divided by the mean of the slowest 1% of frame intervals.
- JS heap: `JSHeapUsedSize` from the Chrome DevTools Protocol at the end of the sample (hub page and module iframe share one heap).
- Draw calls (renderer.info): `renderer.info.render.calls` sampled every frame and averaged, summed over every three.js renderer found through the `__THREE_DEVTOOLS__` hook. three.js resets it on each `render()` call, so a module that renders several passes per frame reports only its last pass here.
- GPU draws / frame: every WebGL `draw*` and WebGPU `draw*` call counted by wrapping the context prototypes, averaged per frame; this covers all passes and non-three.js renderers. `—` means nothing drew on the GPU during the sample.
- Transferred / JS: encoded bytes over the network for the whole run, all resources and scripts only. `pnpm dev` serves unminified sources, so these are larger than production but comparable run to run.
- Page errors: uncaught exceptions during the run.
