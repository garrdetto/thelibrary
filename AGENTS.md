# myWorkHelper

TanStack Start / React 19 site on Cloudflare Workers with four areas: a creative studio (AI chat, images, lyrics), an 8-ball/9-ball pool game, a racing game with two tracks, Thrill Park (an original 3D theme-park builder), and accounts/admin. Live multiplayer for pool, racing and Thrill Park runs on a separate Node service in `server/` (Railway). The initial route must render this product, never a starter demo.

## File map

### Shell and shared UI
- `src/routes/__root.tsx`: document shell, metadata, favicon.
- `src/routes/index.tsx`: navigation, studio tabs (chat, image, lyrics), saved lyric styles, theme picker; mounts pool, account, admin, and lazy-loads racing.
- `src/styles.css`: all styling, CSS tokens, site themes, responsive layouts, reduced-motion and focus states.
- `src/lib/site-themes.ts`: site theme list. `public/`: favicon and images.

### Worker backend (`src/server.ts`, `src/server/`)
- `src/server.ts`: Worker entry. `/api/*` goes to `src/server/api.ts`; everything else to TanStack Start.
- `src/server/api.ts`: route table and error handling.
- `src/server/auth.ts`: PIN hashing (PBKDF2), sessions (`tl_session` cookie), lockouts, admin constant.
- `src/server/routes/account.ts`: `/api/pool-account` (login, logout, multiplayer tickets, ticket redeem), `/api/workspace-access`, `/api/account-settings`, `/api/workspace-admin`.
- `src/server/routes/pool.ts`: `/api/pool-practice`, `/api/pool-preferences`, `/api/pool-cue-overlay`.
- `src/server/routes/racing.ts`: `/api/racing` tickets, lap records, paint profiles, AI skins.
- `src/server/routes/park.ts`: `/api/park` multiplayer tickets (prefix `park:`), ticket redeem, gzip-compressed saves (slot 0 is the 5-minute autosave, slots 1–6 are manual), and per-map company-value leaderboards in `park_scores_by_park` (one row per named park, keyed by `parkId`; it and `park_scoreboard_resets` are created on first use, plus `shot_at`, migration 0012). After every save and autosave of a solo scored park, the HUD posts `score` with `companyValue` (park value + cash − loans), the park name and the save as `snapshot`, then renders a whole-park overview with `ParkRenderer.captureOverview` (owned land framed at midday, JPEG) and posts it as `shot`, stored in KV `park-shot/<parkId>` and served publicly at `?shot=<parkId>`. Parks carry `named`; the HUD blocks play with a naming dialog until the player names the park (the `park` command sets `named`). The board's View button opens `ParkShotDialog.tsx` with the screenshot for anyone, signed in or not; from the menu board it also offers "Walk around in 3D" (`?view=<scenario>&park=<parkId>` returns the snapshot, opened read-only through `ViewSession`). Admin `reset-scores`. The board is `src/components/park/ParkScoreboard.tsx`.
- `src/server/routes/maplestreet-items.ts`: `/api/maplestreet-items`, Maple Street's admin item pipeline. GET lists every published item (public, retired ones included with `active: false` so houses that own them keep them); `?model=<id>` serves the .glb/.gltf from KV `maplestreet-item/<id>` with an immutable cache. POST (admin, multipart: `model` file plus `name`, `price`, `scale` JSON `{x,y,z}`, `room`, `func`, `indoor`, `solid`, `yaw`, `w`, `d`, `h`, optional `status` `draft`/`published`) checks the model with `src/server/gltf-check.ts` (glTF 2.0, ≤ 15 MB, no Draco/Basis, self-contained .gltf), stores it, inserts a row in D1 `maplestreet_assets` (kind `item`; Zod schema `storeItemSchema` in `src/server/maplestreet-items.ts`) and, when published, tells the `MapleStreetWorld` Durable Object to reload the catalog. PATCH (admin, JSON `{id, status?, active?, name?, price?}`) publishes a draft, retires or restores an item. GET lists drafts only to the admin with `?drafts=1` (the response says `drafts: true` when it did).
- `src/server/routes/maplestreet-vehicles.ts`: `/api/maplestreet-vehicles`, published Maple Street vehicles. GET lists every vehicle (public, retired ones included with `active: false` so owners keep them); `?model=<id>` and `?wheel=<id>` serve KV `maplestreet-vehicle/<id>` and `maplestreet-vehicle/<id>/wheel`. POST (admin, multipart: `model`, optional `wheel`, `name`, `spec` JSON checked by Zod `vehicleSpecSchema` in `src/server/maplestreet-vehicles.ts`) stores the record in D1 `maplestreet_assets` (kind `vehicle`) and, when published, refreshes the `MapleStreetWorld` catalog; optional `status` `draft`/`published`. PATCH (admin, JSON `{id, status?, active?, name?, spec?}`) publishes, retires, restores or edits. GET lists drafts only to the admin with `?drafts=1`.
- `src/server/maplestreet-assets.ts`: D1 `maplestreet_assets` (migration 0016, also created on first use and back-filled from the older `maplestreet_items` and `maplestreet_vehicles` tables with `INSERT OR IGNORE`, which are kept but no longer written). One row per admin-published asset: `kind` (`item`, `vehicle`, and later `garment`, `accessory`, `prop`, `building`), `status` (`draft`, `published`, `retired`; `shared/Assets.ts`), JSON `spec` and `files` (role → KV key, type, bytes). Drafts are visible only to the admin and only in the developer instance (`/modules/maplestreet.html?dev=1`, `src/core/DevMode.ts`), a private solo game with its own save. Names with real makes or models are refused.
- `src/server/routes/meshy.ts` + `src/server/meshy.ts`: `/api/meshy`, admin only. Calls Meshy's REST API with the `MESHY_API_KEY` secret (never sent to the browser; Meshy errors are mapped to plain messages). `?status` returns connected, balance and the credit table (`src/lib/meshy.ts`); GET lists jobs and refreshes unfinished ones; POST actions `text` (previews), `image`, `refine`, `remesh`, `retexture`, `cancel` (deletes the task; Meshy doesn't refund started tasks), `hide`. Jobs are in D1 `meshy_jobs` (migration 0015); finished models are stored in KV `meshy-model/<jobId>` and served by `?model=<jobId>`. `MESHY_API_BASE` (dev only) points at `scripts/meshy-mock.mjs`.
- `src/server/routes/site-changes.ts`: `/api/site-changes` (admin chat with Claude that edits and publishes the site; see Site changes below).
- `src/server/routes/scores.ts`: `/api/module-scores` leaderboards for embedded modules (GET `?module=`, POST `score` / `reset-records`). Board settings live in `src/lib/module-scores.ts`.
- `src/server/routes/studio.ts` + `src/server/lyrics.ts`: `/api/studio`, `/api/library?id=` (version history only), `/api/asset`, `/api/learning`, `/api/lyric-presets`.
- `src/server/gemini.ts`: Gemini client from the `GEMINI_API_KEY` secret.
- `src/lib/studio-types.ts`: browser-safe studio types.

Its 3D players (`class Rig`) are 6-ft athletes about 7.5 heads tall (rig units times `RIG_S`): a sculpted chest, pelvis and an abdomen skinned between them, and each arm and leg is one continuous `LimbTube` whose muscle profile (`armProfile`, `legProfile`) rounds through the elbow or knee, so joints stay closed in any pose; hands, fielder's glove and cleats are separate meshes. Batters and runners wear helmets, fielders caps. Sculpted faces and PBR materials (`STD`, `SKIN`, `HAIR`, PMREM sky reflection) are unchanged; `public/modules/faces.png` is not drawn on the models. Field geometry is in world feet with the back point of home plate at the origin (the foul lines run from it); the pitch crosses the zone (`ZZ`, `ZC`, `ZH`) over the middle of the plate. When the user's team fields, the defense never throws on its own: the player clicks a base marker (or presses 1–4) and `userThrow` sends the ball. The HUD shows a ghost ball where the last pitch crossed and a compact release meter beside the zone. Online play in these uses PeerJS room codes, not the `server/` service.

- Thrill Park (`#park`, module id `park`): `server/park/` is the shared simulation (terrain, catalog, coaster track physics, commands, guest and staff AI, finances, snapshots; types in `index.d.mts`). `src/lib/park/` holds the dependency-free WebGL2 renderer (`gl.ts`: smooth-normal mesh builder, sun shadow map with PCF, specular/fresnel lighting, procedural ground and water shading; `models.ts`: guests built by `addPerson` with 8 walk frames plus idle, 8 looks and a near/far detail level, organic scenery; `renderer.ts`: blended terrain with ambient occlusion and shorelines, a shadow pass then the main pass via `drawWorld`), the local and online sessions (`session.ts`) and the saves client (`api.ts`). The guest cap (`spawnRate` in `sim.mjs`) is the smallest of 4 × (30 + rideScore·26 + stalls·8), owned land × `GUESTS_PER_OWNED_TILE` (0.7, counted by `ownedTileCount` in `land.mjs`, cached by `state.landVersion`) and `MAX_GUESTS` (6,400 per park); `p.spawn.limit` says which applies and `GuestCapacity.tsx` shows it. Level land levels the dragged area to the height of the corner the drag started from (`levelStartHeight`, the `terrain` command's `sx`/`sy`). Paths: dragging with any path type quick-draws a straight ground path; clicking starts the coaster-style path builder (turn left/straight/right, stairs/slope/flat sections) whose Auto-finish is the `pathFinish` command, which steps down to the ground or an existing path and builds nothing if it can't. Ride exits can use queue-line tiles: `exitLine` in `guests.mjs` follows them to the footpath and guests walk out along it (`exitRide`/`exitStep`); entrance `queueLine`s never route through exit-line tiles. The renderer puts an overhead sign (`queueSignModel`) where each entrance queue meets the footpath; exits have none. Land is bought one square (`buyLand`) or by dragging an area (`buyLandArea`, `landAreaPlan`, up to 32×32, only squares connected to the park), $100 each. Off-screen guests are culled before instancing (`culling.ts`). Flat rides with `resize` in the catalog (Swimming Pool, Wave Pool) are placed by dragging a footprint (`flat` with `w`/`h`); the entity keeps `size`, and `flatSpec`/`rideFlatSpec` in `flatspec.mjs` give cost, upkeep, capacity and stats from the size and, for rides with `waves`, the `wave` setting (`WAVE_SETTINGS`, changed with `rideSet`). Use `rideFlatSpec` rather than `FLAT_RIDES[...]` for those numbers. The renderer caches flat ride models per kind, size and wave; the Wave Pool model is `src/lib/park/waterModels.ts`. The other water rides (category `water` in `FLAT_RIDES`) are drawn by `waterRideModel` in `src/lib/park/waterRides.ts`, which the renderer tries before `flatRideModel`; keep their tintable surfaces light so the ride color shows. Ready-made coasters with a `footprint` (plus `height` and `cost`, shown on the design cards) must close their own circuit inside that footprint with no auto-complete tail; `park.test.mjs` builds each one to check this, so recompute those fields if track physics or piece costs change. Suspended Looper stations start `INVERTED_STATION_LIFT` (7 half-metres) above the ground. Guest intensity rules live in `server/park/thrill.mjs`: `guestProfile` (kid, casual, or thrill seeker at `THRILL_SEEKER_SHARE`), `intensityLimit` (maxI plus `warm` plus the friends nudge from `state.thrillCrowds`), `warmUp` and `lovesRepeats`. Guests carry `type` and `warm`; older saves default to casual or kid. Ride comments come from `server/park/comments.mjs` (`COMMENT_POOLS`, `recordComment`, `rideComment`; lines are picked by a hash of guest, ride and time, never `Math.random`). The ride window's "What guests are saying" (`RideComments.tsx`) fetches them through `session.rideComments(id)`, which reads local state or sends the `ride-comments` socket request online. Hotels are entities of type `hotel` (`server/park/hotels.mjs`: `HOTELS` styles, `HOTEL_ADDONS`, `hotelSpec` for rooms/cost/upkeep/guest bonus, `updateHotels` each new day for occupancy and income, `hotelSpawn` for guests leaving hotel doors, `resortHotels` for districts). They are placed with `hotel` and edited with `hotelSet`; the HUD's Resorts tab and hotel window are `ResortPanel.tsx`, and `src/lib/park/hotelModels.ts` builds each style's mesh from its size, floors, colors, roof and add-ons. `src/components/park/ParkGame.tsx` is the menu and lobby, and `ParkHud.tsx` is the in-game interface. Thumbnail: `public/images/modules/park.webp`.
- Leaderboards: 2048, Chopper Cave and BotWreck 3D load `public/modules/module-scores.js` and call `tlScores.submit(module, value)`; it posts to `/api/module-scores` and messages the parent `{type:'tl-score-saved'}` so `ModuleScoreboard.tsx` (shown under the module frame) refreshes. Boards list every saved result, top 10, so one player can hold several places. Short Track Showdown uses the racing lap records (`LapRecordBoard`) instead.

### Site changes (admin asks Claude to change the site)
- `src/components/SiteChanges.tsx` is a chat with Claude. Each admin message becomes a row in D1 `site_changes` (migration 0009, also created on first use) and `/api/site-changes` (`src/server/routes/site-changes.ts`) starts `.github/workflows/site-change.yml` through the GitHub API (`workflow_dispatch` with `job_id` and `callback_url`).
- The workflow runs `.github/site-changes/run.mjs`: it fetches the job and earlier turns from `/api/site-changes?job=` (Bearer `SITE_CHANGES_SECRET`), runs Claude Code headless with the request, reports progress back, then builds (`pnpm build`), commits to a `site-change/<job>` branch and opens a pull request. With auto-publish it enables squash auto-merge and waits for the `modules` check, reporting the squash commit on `main`; otherwise the pull request waits for review. The publish step uses the `CLAUDE_GITHUB_TOKEN` repository secret when present, because pull requests opened with the built-in token never trigger the check. New migrations are applied when Cloudflare secrets exist. Runs are serialized with a concurrency group. Undo runs `git revert` on the change's commit.
- Credits: Anthropic has no API for a prepaid balance, so the admin enters the balance and the panel subtracts each run's reported `total_cost_usd`. With `ANTHROPIC_ADMIN_KEY` set, it also shows the organization's month-to-date spend from the Admin cost report (cached 5 minutes in `site_change_settings`).
- Worker secrets: `SITE_CHANGES_GITHUB_TOKEN` (fine-grained token, Actions read/write on the repo), `SITE_CHANGES_SECRET`, optional `ANTHROPIC_ADMIN_KEY`, optional `SITE_CHANGES_REPO` (default `garrdetto/thelibrary`). Repository secrets: `SITE_CHANGES_SECRET`, and `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`; optional `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` for migrations; optional repository variable `SITE_CHANGES_MODEL`.

### Multiplayer server (`server/`)
- `server/index.mjs`, `server/racing.mjs` and `server/park.mjs` verify players by redeeming tickets at `<site>/api/pool-account?action=redeem`, `<site>/api/racing?action=redeem` and `<site>/api/park?action=redeem`. `FRONTEND_ORIGIN` must list the site origin.

## Conventions

Use TypeScript, descriptive identifiers, React hooks, and type-only imports. Keep provider SDKs and database imports out of client modules. Server and database relative imports use `.js` extensions. Validate runtime input with Zod. Preserve the CSS token system, responsive layouts, reduced-motion support, keyboard accessibility, and loading, empty, and error states. Do not add inline comments unless requested. Prefer adding new modules over growing the already large files.

## Platform rules

- All AI runs server-side: Gemini with the Gemini API key secret, and Meshy 3D generation (admin only) with `MESHY_API_KEY`. Text uses `gemini-3-flash-preview`; images use `gemini-3.1-flash-image`. Never expose environment values or provider errors.
- Use D1 for structured records and KV for binary data. Never use local files, browser storage, or in-memory persistence for data that must persist.
- Schema changes go in a new numbered file in `migrations/` and are applied with `wrangler d1 migrations apply thelibrary-db --remote`.
- Non-GET endpoints check same origin. Ticket redeem endpoints are server-to-server and skip it.

## Accounts and access

- Accounts are a username (3–20 letters, numbers, `_`, `-`, stored lowercase) and a password of 3 or more characters (up to 128), hashed with a per-user salt. Older accounts created with 3 digits keep working. No registration page, email or recovery: an unknown username creates the account; a known username with the wrong digits returns "Invalid password."
- Wrong passwords lock the username after 5 attempts (15 minutes, doubling each time up to 24 hours) and the network after 25. Each network can create 10 accounts per day.
- The administrator is `stoegbauer`, whose password is the `ADMIN_PASSWORD` secret . The admin can rename accounts, grant studio pages, reset a password (next sign-in sets the new password) and delete accounts.
- Studio pages (chat, image, lyrics) require a grant from the admin. Pool and Racing require sign-in for saved data.
- Pool appearance, cue overlay, racing paint, lobby sound, site theme, saved lyric styles and lyric corrections are stored per account. There is no creation library; creations are kept only so revisions and version history work. Never include `user_id` in API responses.

## Studio rules

- Never claim chat includes live browsing or personal document retrieval.
- New lyrics, fine-tunes (`revise`), full rewrites (`revamp`), and manual edits are distinct. Fine-tunes are surgical, accumulate in `tuning`, and keep untouched lines. Revamps rewrite every line with current settings and keep the topic. Every derived version stores `parent_id`.
- Saved lyric styles store the full song settings including `instructions`, the user's standing writing directions, which the model follows as preferences under the mandatory rules.
- Explicit mode (default on) allows profanity but never slurs against protected groups.
- Artist influence and custom genres are researched server-side and cached in `research`, which is never public.
- Prompt text and instructions are ideas only: lyrics copying 4–5 word runs are regenerated once, then rejected. The validator requires bracketed sections and forbids intro lyrics.
- Image downloads are re-encoded through canvas. Serve stored images only through the ownership-checked `/api/asset`.

## Games rules

- `server/racing-engine.mjs` is shared by browser and server. Any change to it, or to server lobby/race code, requires redeploying the multiplayer service; bump the `/version` string in `server/index.mjs` and note it in `server/README.md`.
- Keep single-player and multiplayer physics identical by changing the shared engine rather than duplicating logic in `Racing.tsx`.
- Lap records are stored per track and mode. Short Track Showdown (`modules-src/shorttrack/`, served as `public/modules/shorttrack.html`) posts to `/api/racing` with track `shorttrack` (Showdown Bullring), `dells` (Dells Short Track), `dellswide` (Dells Wide Oval: the Dells layout 8° flatter, 30 m turn radius, 10% wider, bare grass infield with no pit road, garages, haulers or pylon via `bareInfield`), `prison` (Prison Speedway: a blend of the three asphalt layouts with more grip for every car, `theme:'prison'` adds the castle-style stone guard towers, crenellated curtain wall, razor wire, night searchlights and orange-clad inmate crowd from `modules-src/shorttrack/prison-speedway.js`) or `dirt` (Dells Dirt Oval, dirt handling; picked in the module menu via `?track=`) and modes `time-attack`, `race` (shown as Solo Race) and `multiplayer`; races start with a half-lap rolling start from the back stretch, two wide with a car length between rows (`GRID_S`, `GRID_ROW`); the AI drives every car, the player's included (`c.auto`), in a rigid formation at `FORM_V` (the slowest centerline speed both files can hold through the turns, at most `CFG.aiPaceSpeed`) until the leader takes the green at the line, then the player takes over; `AI_LEVELS` sets AI corner skill, braking, passing reach and aggression, while traffic awareness is the same at every level (path scan for the car ahead with a stopping-distance speed limit, `laneClear` sweeping the whole lane change, `passLane` picking the inside or outside, wreck avoidance via `isHazard`, lifting near the wall, catching slides, and a bump-and-run when held up: `bumpT` closes at a tap, and a tapped AI gets loose for `looseT`), and AI liveries come from `randomLivery` (random colors, pattern, number font/style/colors) each race; every completed lap by the signed-in driver is sent (every time attack lap, and every race lap until that driver takes the checkered flag), and boards list every lap, so one driver can hold several places. The truck body is the owner's race-truck model (lofted body, greenhouse, roll cage, fascia, bed wing), embedded in the module as `TM` and scaled to the physics size; liveries are conforming decal meshes on the sides, hood and roof. Race numbers come from `modules-src/shorttrack/shorttrack-numbers.js` (20 Google Fonts digit subsets, 11 styles plus slant, size 60–150% with 125% default, fill/outline/accent colors) and sit on their own decals on the doors, roof and tailgate; `cleanLv` keeps older liveries and older peers working (`italic` becomes `block` plus slant). Drivers pick a vehicle on the track screen or in the garage, stored as `veh` in the livery (`truck` or `car`): the car is a plain super late model loaded from `public/modules/shorttrack-car.bin` (decimated from the owner's model with its original graphics removed), built by `buildStockCar`. Its paint faces carry atlas UVs (side, roof, rear and front regions listed in the file's `regions`), and `carLiveryTex` paints the livery pattern and race numbers into one texture in world metres (`CAR_NUM_SPOTS` sets the door, roof and tail number spots). It uses the truck's scale, physics and dimensions. AI fields use the host's choice; the pace vehicle stays a truck. `src/components/LapRecordBoard.tsx` shows the all-time top 20 per mode (tabs) under each racing module page: Max Secure Circuit and Oval Speedway via `Racing.tsx`, Short Track Showdown under its iframe. `GET /api/racing?records` is public; the module posts `{type:'tl-lap',track}` to the parent after a saved lap so the board refreshes.
- `server/park/` is shared by browser and server in the same way: change park rules there, never in the UI, and redeploy the multiplayer service afterwards. Online parks are server-authoritative: clients replay structural commands in server order, and dynamic state arrives in snapshots. Keep commands free of randomness so the replay stays identical.
- Thrill Park is an original game. Keep its names, rides, scenarios and art original; do not copy assets, names or branding from commercial games.

## Development

Read docs/ENGINE-MAP.md before changing any module; keep it current. The shared 3D engine is `engine/` (barrel `engine/index.ts`); a new 3D module starts as a copy of `modules-src/_template/` renamed without the `_`, and `pnpm engine:smoke` checks the template in a hub-like iframe.

Install with `pnpm install`; develop with `pnpm dev`. Every change reaches `main` through a pull request: the `modules` workflow (`.github/workflows/modules.yml`) runs `pnpm assets`, `pnpm build` and `pnpm test`, and `main` requires it. `pnpm gate` (`scripts/module-gate.mjs`) loads every embedded module in the hub iframe with Playwright and reports console errors and screenshots. The 3D code index is `docs/ENGINE-MAP.md`; update it whenever a file it lists changes. Pushes to `main` build and deploy automatically through Workers Builds.

- Chat: floating `GroupChat` component (src/components/GroupChat.tsx) polls `/api/group-chat` (D1 `chat_messages` + `chat_presence`, migrations 0002–0003). `thread` NULL = everyone; otherwise the sorted comma list of member usernames (private chat, up to 8). Presence (who's online) comes from these polls, not Railway. Read receipts: viewing a thread posts `{action:'read', thread, id}` to `/api/group-chat` (table `chat_reads`, migration 0005, also created on first use); polls return other members' read marks and your latest message shows Sent / Seen / Seen by. A thin bar attached under the chat button shows "x players online" with a green dot and opens the Online tab; signed-out visitors get the number from the public `GET /api/group-chat?count`. Invites: `meta.invite` {module,label,code}. Embedded modules with online rooms (sandlot, chess, checkers, shorttrack) answer `postMessage({type:'tl-host'})` with `{type:'tl-room', code}` and auto-join from `?room=`. No popups or sounds: while anything is unread the chat button flashes between pink and the accent color and the browser tab icon blinks a red dot (`src/lib/use-blinking-favicon.ts`), even with reduced motion on, until the messages are read.
- Themes: midnight / slate (label Gray) / light. Hub, sidebar and chat colors come from `--lib-*` variables per theme in styles.css; old theme ids map to these in site-themes.ts.
- Record resets: each high-score board registers its currently selected tab with `useRecordResetTarget` (`src/components/AdminRecordReset.tsx`). Only the admin sees the reset button, rendered at the very bottom right of every page by `AdminRecordResetButton`; it clears just the selected board. Reset endpoints accept the admin session (the old reset password still works server-side).
